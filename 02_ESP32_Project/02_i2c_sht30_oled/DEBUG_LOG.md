# Stage 2.1 调试记录：I2C总线通信失败排查

> 日期: 2026-07-30 | 硬件: YD-ESP32-S3 + SHT30 + SSD1306 OLED

---

## 问题总结

**根因**：I2C总线缺少外部上拉电阻（SDA/SCL各需4.7KΩ上拉到3.3V），导致总线无法正常通信。

---

## 排查过程

### BUG-001: 编译错误 `multi-line comment`

| 项目 | 内容 |
|------|------|
| **现象** | `cc1.exe: error: multi-line comment [-Werror=comment]` |
| **根因** | `ssd1306_font.c` 第139行注释 `// 0x5C \` 末尾的反斜杠被C编译器当作续行符，吞掉了下一行代码 |
| **修复** | 改为 `// 0x5C backslash` |
| **教训** | C语言中 `\` 是续行符，注释里也不能用 |

### BUG-002: I2C总线通信失败 `ESP_ERR_INVALID_STATE`

| 项目 | 内容 |
|------|------|
| **现象** | SHT30和SSD1306都返回 `ESP_ERR_INVALID_STATE`，I2C transaction 全部失败 |
| **受影响设备** | SHT30 (0x44) 和 SSD1306 OLED (0x3C) —— 两个不同地址的设备都连不上 |
| **排查1: 交换SDA/SCL** | GPIO6↔GPIO7交换 → 无效 |
| **排查2: 降I2C速度** | 100KHz → 10KHz → 无效 |
| **排查3: 换GPIO引脚** | GPIO6/7 → GPIO4/5 → 无效 |
| **根因确认** | I2C总线缺少外部上拉电阻。ESP32内部上拉约45KΩ，驱动力太弱，无法满足I2C时序要求 |
| **解决方案** | 在SDA和SCL各接一颗4.7KΩ电阻到3.3V |
| **数据手册依据** | I2C规范要求：总线电容≤400pF时，上拉电阻典型值4.7KΩ（标准模式100KHz） |

### 排查验证矩阵

| 测试 | GPIO | I2C频率 | 上拉 | 结果 |
|------|------|---------|------|------|
| 1 | 6(SCL)/7(SDA) | 100KHz | 仅内部(~45KΩ) | ❌ ESP_ERR_INVALID_STATE |
| 2 | 6(SCL)/7(SDA) | 10KHz | 仅内部 | ❌ 同上 |
| 3 | 5(SCL)/4(SDA) | 10KHz | 仅内部 | ❌ 同上 |
| 4 (待验证) | 6/7 | 100KHz | 外部4.7KΩ×2 | ⬜ 等待电阻到货 |

## 接线上拉电阻方案

```
        3.3V
         │
    ┌────┼────┐
   4.7KΩ     4.7KΩ
    │         │
  GPIO7     GPIO6
  (SDA)     (SCL)
    │         │
    └────┬────┘
         │
    SHT30 + OLED
    (共用I2C总线)
```

## 经验教训

1. **I2C必须接上拉电阻**：这是硬件定律，不能用软件绕过。降速、换引脚都无效
2. **先验证总线再找设备**：两个不同地址的设备同时连不上 = 总线问题，不是设备问题
3. **排查要有矩阵意识**：逐一排除变量（引脚、速度、上拉），不要同时改多个变量
4. **数据手册是铁律**：ESP32-S3数据手册明确建议I2C使用外部上拉，内部上拉仅作辅助
